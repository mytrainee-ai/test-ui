# Math Page Vision Lab

Локальное учебное приложение: показывает, как Vision LLM читает **одну** страницу учебника математики и превращает её в структурированный JSON и Markdown с формулами LaTeX. Интерфейс на русском языке. PDF обрабатывается как изображение выбранной страницы; текст напрямую из PDF не извлекается.

## Требования

- Python 3.12
- Доступ к OpenAI API и API-ключ с доступом к модели, принимающей изображения и структурированный вывод
- Интернет для запроса к API

## Установка: Windows PowerShell

В каталоге проекта выполните:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Если PowerShell запрещает активацию скриптов, можно запускать команды через `.\.venv\Scripts\python.exe -m pip ...` и `.\.venv\Scripts\python.exe -m streamlit run app.py` без активации.

## Установка: Linux/macOS

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

В `.env` вставьте свой `OPENAI_API_KEY`. По умолчанию там указан `OPENAI_MODEL=gpt-4.1-mini`; при необходимости поменяйте модель вручную. Настоящий `.env` и ключи не добавляйте в Git.

## Запуск

После активации `.venv`:

```bash
streamlit run app.py
```

Откройте адрес, который напечатает Streamlit (обычно `http://localhost:8501`). Загрузите JPG, JPEG, PNG или PDF до 15 МБ. Для PDF выберите страницу, посмотрите исходное изображение и нажмите **«Распознать страницу»**. Результат доступен во вкладках «Просмотр», «Markdown» и «JSON». Кнопки скачивания сохраняют UTF-8 файлы `math_page.md` и `math_page.json` без нового API-запроса. При смене файла или страницы старый результат сбрасывается.

## Что происходит при распознавании

1. Pillow проверяет изображение, а PyMuPDF превращает только выбранную страницу PDF в PNG с разрешением 200 DPI.
2. Приложение отправляет изображение и инструкцию в OpenAI Responses API одним основным запросом.
3. OpenAI SDK использует Pydantic-схему для структурированного вывода. Приложение дополнительно проверяет уникальность `id` и непрерывный порядок `order`.
4. Markdown строится локально из **того же** проверенного JSON. Второго запроса к модели нет.

Пример сокращённого JSON:

```json
{
  "document": {"filename": "page.png", "page_number": 1, "language": "ru"},
  "elements": [
    {"id": "element_001", "order": 1, "type": "heading", "text": "Квадратные уравнения", "latex": null, "description": null},
    {"id": "element_002", "order": 2, "type": "formula", "text": null, "latex": "ax^2+bx+c=0", "description": null}
  ]
}
```

## Ограничения и данные

Это эксперимент по извлечению информации, а не проверка математической правильности. Модель может ошибиться в символах, формулах, таблицах, рисунках и порядке чтения. Она не должна самостоятельно решать отсутствующие на странице задачи, но результат всё равно стоит сверять с исходником. Поддерживается одна страница за запрос; пакетной обработки и локальной базы данных нет.

**Изображение выбранной страницы отправляется во внешний OpenAI API** и может обрабатываться согласно условиям провайдера. Запросы к API могут стоить денег. Приложение не сохраняет загруженный документ автоматически и не отправляет остальные страницы PDF.
